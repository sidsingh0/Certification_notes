## Cluster Modes
1. Single Mode (1 Master, 0 Workers): For development and lightweight purposes
2. Standard Mode (1 Master, custom number of workers): For production and flexibility
3. High Availability Mode (3 Masters, custom numbers of workers): When we cannot tolerate downtime. Critical Workloads.

## Post Setup
- We can update number of workers
- We can add/remove number of pre-emptible workers
- We can change the labels of the resources(for organization)
- Graceful decommisioning toggle (used during downscaling, removing workers)
- **Note: Dataproc manages resharding of data whenever we downscale/upscale the cluster**

## Pre-emptible nodes
- Cheaper but can be reclaimed by google
- **Atleast one standard worker node is required** to use pre-emptible worker nodes
- Best for compute-intensive tasks that can handle interruptions and don't require persistent storage.
- Dataproc manages addition/removal of pre-emptible nodes
- Jobs take less time

## Graceful Decomissioning [IMPORTANT]
- Helps us remove the worker node safely without interrupting ongoing jobs
- Re-distributes data to other nodes to prevent data loss
- Really helpful during scaling down.
- Applies only to standard worker nodes. Pre-emptible nodes can be reclaimed anytime, without warning, so graceful decomissioning is not possible.
- They are especially important when we use mixed nodes (standard + pre-emptible), since preemptible nodes can be reclaimed at any time, critical workload has to continue on standard nodes, agar wo bhi aese hi leliye to job complete hi nahi hogi.
- It is not turned on by default.
