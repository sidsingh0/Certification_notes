# PITR
- Allows us to roll back the database to a previous state.
- Cloud SQL approaches PITR changes based on engine being used.
	1. MySQL
		1. It uses Binary Logging
		2. It records all the changes made to the database after a transaction completes, in binary format
	2. PostgreSQL
		1. It uses Write ahead logging (WAL)
		2. Postgres engine logs the changes before actually committing the changes to the database, in this way the integrity is maintained

# High Availability and Disaster Recovery
- Failover replicas can be created to ensure high availability and DR
- The replica can be deployed in:
	- Same region but different zone as the master
	- Different region as the master
- *These replicas are consistent with the master and there is synchronous replication*
- Applications read ONLY from the master at first, if there is an outage in master's zone, communication switches to failover replica.

# Read Replicas
- Used to increase the reading throughput of the database
- Improves scalability and availability.
- Limitation: 
	- Read replicas must be in the same region as the master DB
	- The replicas are synced asynchronously, so stale data might be served to the customers
