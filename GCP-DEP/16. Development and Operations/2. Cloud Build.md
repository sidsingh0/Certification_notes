Here is what is actually happening behind the scenes:
#### 1. Same Worker VM, Different Docker Containers
- **One Machine:** The entire build pipeline runs on **a single underlying VM** (called a Cloud Build worker) provisioned just for your build.
- **Containers, Not VMs:** Each step listed under `steps:` runs inside its own **Docker container** on that same VM.
#### 2. How the Execution Works
When Cloud Build runs this YAML:
1. **Step 1 (`npm install`):** Cloud Build spins up a container using the `gcr.io/cloud-builders/npm` image, runs the install, saves files to a shared working folder, and turns off that container. 
2. **Step 2 (`npm run test`):** It spins up a fresh container using the same `npm` image to run tests on the files created in Step 1.
3. **Step 3 (`docker build`):** It spins up a container with the Docker CLI (`gcr.io/cloud-builders/docker`) to package your app into an image.
4. **Step 4 (`docker push`):** It uses the Docker container again to upload that image to Google Container Registry.
5. **Step 5 (`gcloud app deploy`):** It spins up a container with the Google Cloud SDK (`gcr.io/cloud-builders/gcloud`) to send the deploy command to App Engine.
#### Key Takeaway
> All steps share **the same underlying VM instance** and a **shared workspace directory** (`/workspace`), but each individual step is executed in a fresh, isolated **Docker container**.
