There are 2 delivery semantics for Pub/Sub:-
1. **Atleast once delivery**
	1. In this case, message is guaranteed to be delivered atleast one time to the subscriber
	2. Duplicates may occur 
	   (network issues, client retries, or expired acknowledgement deadlines can cause the same message to be sent more than once.)
	3. Default method for delivery semantic
2. **Exactly once delivery**
	1. In this case, message is guaranteed to be delivered exactly one time
	2. No message is lost and **no duplicates occur** (However there are edge cases, so we should make our application idempotent)

### Acknowledgement Deadline
- Once the message is delivered to the subscriber,
  Subscriber has certain amount of time to send back ACK
- If Subsciber takes too long to send ACK, or is unable to send ACK, 
  message delivery is retried
- Maximum acknowledgement deadline can be 10 minutes, default is 10 seconds
	- We can extend acknowldgement deadline, if our process requires more time
	- We can shorten it too, for faster retries
