### Message Retention
Time period for which Pub/Sub retains the message, before finally deleting it.
Calculated from Publish time
This allows messages to be replayed.

There are 2 types:-
1. **Topic Retention**
	1. Stores all the messages published in a topic
	2. Even the acknowledged ones
	3. Therefore this is very useful for auditing
	4. Default time is 7 days can be increased to 31
2. **Subscription retention**
	1. It is for a particular subscription
	2. It stores the unacknowledged messages for the subscription
	3. So if a subscriber goes down, messages can be delivered when it comes back up again
	4. Default is no retention, however max is 31 days

### Snapshots [Important]
- We can take a snapshot of a subscription state.
- This snapshot can be used as a recovery point for potential future use.
- Use case:
	- Suppose we have a new logic update on the subscriber side
	- Now the logic got messed up and subscriber went down
	- Important data is lost, to prevent this we can roll back to the recovery point of the subscription
	- Once you roll back (seek) to the snapshot, Pub/Sub will redeliver the messages from that point onward, allowing your fixed subscriber logic to process them correctly.

### Seek feature
- Allows us to change acknowledgement state of messages in bulk
- This allows us to replay already acknowledged messages
- We can:
	- Seek into a snapshot (Known good state)
	- Seek to a specific time (retention has to be setup)
