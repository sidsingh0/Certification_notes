Publisher is an entity (application/service) that creates and sends messages.
Publisher does not need to know who it is sending messages to.
Subscriber is the entity that recieves the messages from Pub/Sub.
Upon recieval of message, subscriber informs Pub/Sub that the message has been recieved
Subscriber does not have to know anything about the publisher either.
![[Pasted image 20260724231324.png]]
Number of subscribers and publishers are not inerdependent
Main point: Each subscriber gets it own copy of the message, no matter the number of subscribers.
So one message can be processed by multiple subscribers.

### Subscription Types:
1. Push
	1. For real-time, streaming loads
	2. Pub/Sub initiates the process for sending the message
	3. We need a valid Webhook HTTPS api to get messages from Pub/Sub
2. Pull
	1. For large batch loads & when immediate reciept is not required
	2. Here, Client asks Pub/Sub for messages from the Pub/Sub
	3. **Generally requires more code**
