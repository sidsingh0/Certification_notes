## Shared VPCs
- Shared VPCs, allows multiple Projects(Resource groups) in an organization, to use the same VPC.
- Benefits:
	- **Direct communication between different projects with each other over internal private IPs without needing complex setup, VPNs, or public internet exposure.**
	- Centralized management: Network administrators control security, firewalls, and IP spaces in the **Host Project**.
	- Cost savings : Since each Project can use the common network appliances (Load balancers, firewalls, etc.)
	- Consistent security policy applications
- Components:
	1. Host Project:
		- Acts as the central administrator
		- **Best Practice:** It should only contain network appliances and not computes, databases etc. 
	2. Service Project:
		- Separate projects, where teams actually run their applications
		- It contains, VMs, Kubernetes clusters, Databases, pipelines etc.
		- Service projects can be assigned to a relevant subnet

#### Granting service account access in shared VPCs
- Service accounts inside of service projects should be granted ***compute.networkUser*** role on the shared VPC subnetworks in the host project, so it can access the network resources.
- Dataflow pipeline's service account should be given this role to deploy the shared VPCs.

## VPC Peering
- VPC peering allows us to connect 2 VPC networks, so that they can communicate using internal, private IPs.
- Uses internal network
- It works for both same organization, as well as different organizations.
- It also allows different account VPCs to connect to each other

## Cloud VPN
- Uses public network only
- Allows a GCP network to connect with on-prem network or a different cloud provider's network.

## Cloud Interconnect
- Uses a dedicated private network path
- It offers private, high bandwidth connection from on-prem to GCP.
- Use case:
	- When the company does not want to use public internet
	- Regulatory requirements
	- Low latency, high throughput
		- Which is required for large data replication, disaster recovery and real time processing.
