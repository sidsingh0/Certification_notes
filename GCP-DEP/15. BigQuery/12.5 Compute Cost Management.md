2. If using Web Console(interactive query ui), while we write the query, it gives us a preview number of bytes that will be processed by the query.

# BigQuery Slots
- BigQuery's unit of computation are slots.
- It represents the amount of cpu and memory that will be used to run a query.
- ![[Pasted image 20260804002539.png]]
- This is wonderful, because bigQuery evaluated the amount of slots that might be required for the query, and allot computatio units based on that, it can essentially scale up and down dynamically based on query. It can also pull in/remove slots as the query is executed, **this makes BigQuery fully managed.**
- There are two pricing options:
	1. On-demand:
		1. Pricing based on volume of data scanned (per TiB processed)
		2. Constraint: **2000 slots per project**
		3. No upfront cost
		4. It is cheaper in case of:
			1. Low data volume
			2. Highly partitioned and clustered tables: Since query will have to only scan less amount of data
			3. Bursty/intermittent loads
			4. ad-hoc queries
			5. variable workload
	2. Capacity based:
		1. Capacity pricing charges per **slot-hour**
		2. There is a upfront cost
		3. Use when we know the approximate number of slots that will be used
		4. Slots are reserved in advance, for any extra slot that might be used, **autoscaling** (pay-as-you-go per slot-hour) can be added on the top.
		5. More slots -> **Faster execution**
		6. It is cheaper in case of 
			1. heavy workload, continous streaming
			2. We also get discount on commitment duration
		7. It also allows centralized management of slots(across departments), since we have reserved the slots to ourselves.

# Custom Query Quotas
- We set quotas on per query basis. This quota is based on number of bytes read by the query.
- This allows us to do 2 things:
	- Limit the number of bytes read
	- Number of queries run
- We can set it up at 2 levels:
	- Project Level
	- Principal Level: Quota per user
- This allows us to prevent accidental overspending.
- Ensure fair usage amongst members(Noisy neighbour problem irl)

# How to optimize compute costs
1. Combine pricing models:
	1. We use capacity based for our predictable workloads and on-demand for ad-hoc queries.
	2. So for example, if we have a query that runs daily at 7 a.m. we can do capacity reservation for that.
	3. We can assign specific queries to slots we have at hand.
	4. We can use for example, reservation for production queries and on-demand pricing for analytics queries.
2. Set Query Quotas
	1. At principal(level) or project level
	2. Based on number of queries or bytes
3. Monitor and adjust
	1. Regularly review our slot usage.
	2. We can review our slot usage and query performance.
	3. For example, if we see a lot of ad-hoc queries, we can update our slot reservations to include more slots.
	4. Use cloud monitoring or BQ's built in tools
