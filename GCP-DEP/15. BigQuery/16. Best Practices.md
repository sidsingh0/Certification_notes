# Query Best Practices
1. Instead of using select \*, we should specify the column names, this removes unnecessary column scanning
2. Pay attention to the size of data query will scan, before running it.
3. LIMIT and HAVING, do not filter the data before scanning. Therefore they have no effect on scan size.  On the other hand, WHERE clause filters the data before scanning.
4. Establish Logic of the query on small subset of the data first, before running the query on full data. (Since it is expensive)
5. Save intermediate tables and queries, and use them instead of repeatedly querying the original data. This reduces repeated computation and reduces costs.
6. While joining the tables, use INNER JOIN instead of WHERE clause. WHERE clause requires more computation.

# Data Ingest and Storage Best Practices
- Streaming Ingest is expensive.  Use Batch Ingest when possible.
- Smaller tables (especially through partitions) optimize the storage costs. However balance this with costly joins when querying multiple partitions. Since the whole point of denormalizing was reducing the JOINS.
- Nested and denormalized tables reduce the need of JOINS and improve performance, since BigQuery is a columnar database.
- Use expiration settings on datasets, tables and partitions, to remove unneeded data. This reduces storage costs.
- Use long term storage wherever possible
