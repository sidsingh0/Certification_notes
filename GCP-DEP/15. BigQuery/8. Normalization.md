# Denormalization
- Due to performance decrease as a result of normalization, we can denormalize
- It refers to clubbing of related tables into one
- This can improve performance in large datasets, since we do not need to use joins anymore.
- It can also lead to redundancy in data. for example in first slide, same customer name appears multiple times
- We need to balance this redundancy and performance.

# Denormalization in BigQuery
- BigQuery pushes us to denormalize for cost and performance reasons
- Since it uses columnar storage which scans data more effeciently
- Reduces JOIN operations
- To make this even easier, BigQuery allows the use of nested tables and repeated fields to store complex data in a single table.
Ex. Table: Orders
+----------+---------------+-----------------------------------------------+
| Order_ID | Customer_Name | Items (ARRAY of STRUCTs)                      |
+----------+---------------+-----------------------------------------------+
|          |               | Product_Name                   | Price                                |
| 101   | Alice       |----------------------------------------------------------|
|          |               | Laptop                               | 1200                                |
|          |               | Mouse                               |   25                                  |
+----------+---------------+-----------------------------------------------+
- *These nested structures are defined by RECORD/STRUCT datatype*
- To flatten or normalize the data we use *UNNEST*
- BQ Does support JOIN but try to denormalize whereever possible
