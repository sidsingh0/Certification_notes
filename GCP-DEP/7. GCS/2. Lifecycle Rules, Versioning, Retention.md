# Lifecycle rules
- same as amazon
- we can transition data to different storage classes or delete them based on the age of the data, ex. delete outdated data
- help reduce cost
#### Autoclass
- same as amazon
- classes based on access patterns
- not enabled by default
- still potentially more savings with lifecycle rules(since it starts all the data from standard class)
# Object Versioning
- same as amazon (delete markers)
- `gsutil versioning set on gs://bucket_name`

# Retention Policy
- same as amazon
- CANNOT BE USED WITH VERSIONING
- Retention Policy sets a retention period, during which **no objects can be deleted or replaced.**
- Once enabled for a bucket, it applies to all the existing objects + new objects
- Very useful for regulatory and internal governance compliance
- Now, we can change retention policies, however to make it more strict, we have:
#### Bucket Lock
- Bucket lock locks the retention policy, making it permanent, it cannot be removed or reduced
- It prevents bucket deletion too! Once all the objects have completed their retention period, only then the bucket can be deleted
- Retention policy cannot be deleted but can be extended
- Best for data retention regulations
