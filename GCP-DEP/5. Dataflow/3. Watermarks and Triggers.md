## Watermarks
- They tell system till where the system has processed the data
- This tells the system for a time window that the data has been processed correctly
- In case there is a failure or a delay in a processing step, the watermark does not advance, it just waits
- It makes sure no data is left behind
- **Late arriving data:** The system can process the late arriving data as long as the watermark has not moved past the data

Event time: When the data was generated
Processing time: When the data reaches the system

- We might think the data that arrives late is processed late
- However, watermarks are based on **Event time not Processing time**. Therefore late arriving data, is also **processed in correct order.**

#### Then what is the point of the watermark?
In the above case all the data is processed
The watermark is mainly used for **windows**.
Suppose you're counting sales from **7 PM–8 PM Yesterday**.
Dataflow waits until the watermark passes **8 PM** before saying:
 "I think no more events for this window will arrive."
Then it closes the window and outputs the result.
#### When is data NOT processed?
Only if it is **too late**.
For example:
Suppose
- Watermark = **5:10 AM Today**
- Allowed lateness = **10 minutes**
Now an event arrives with timestamp: **7:45 PM Yesterday**
That event is **many hours behind** the watermark.
It is considered **late data**.
Depending on your pipeline:
- ❌ It may be dropped.
- ✅ Or accepted if you configured a large allowed lateness.


# Triggers
- Conditions that define, when the aggregated result of the data in a window should be outputted
- Important in unbounded/streaming pipeline
- With use of trigger, the following thing becomes possible:
	- In case the watermark has already passed the event time, **Late arriving trigger** can cause the window to be reprocessed with the new data.
- Types:
	1. Event time trigger
		1. Fires when watermark reaches a certain time in streaming pipeline
		2. Used for late arriving data
	2. Provessing time trigger
		1. Fires based on real life time
		2. Ex. Fire every minute or every hour
	3. Data driven trigger
		1. Triggers based on quantity or characteristics of data 
		2. Ex. Fire when system has accumulated 100 records, data has reached specific size
		3. Ex. when some value is reached or a pattern is detected
