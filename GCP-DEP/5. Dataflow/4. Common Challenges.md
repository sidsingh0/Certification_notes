## 1. Increased Latency
We should look out for:
1. Increased end-to-end latency
2. Increased per-stage latency

Indicators:
1. Some stages taking longer than expected
2. Too much data in the backlog
3. High latency values in the monitoring dashboard

Troubleshooting:
1. Check logs for the pipeline and the workers processing the pipeline
2. **Data Skew:** One worker is taking on more work than expected
3. Check the pipeline dependencies
4. Resource limitations for the worker nodes
5. Identify the bottlenecks where latency is higher

## 2. Missing Messages in Streaming Pipeline
We should look out for:
1. Gaps in data
2. Sudden drop in throughput
3. Incomplete aggregations (Aggregations do not include some data points)

Troubleshooting:
- Run a batch of the streaming pipeline data and compare the output. Steps:-
	1.  Store incoming stream data into Cloud Storage or Big Query (Do we use Side Output for this? NO, since generally our data might come from Pub/Sub, we can just create a Big Query subscription for that)
	2. Modify the Dataflow job configuration to process the stored data as in the **Batch Mode**
	3. Compare results:
		- If there are differences in output, it means that the streaming configurations (windows, and triggers are setup incorrectly)
		- If the output is same, we need to investigate further, check for:
			1. Streaming pipeline's windowing and triggers
			2. Resource allocation settings

## 3. Out of Order data
We use a combination of Windows, Watermarks and Triggers
Trigger will be setup to process the late arriving data(stragglers)
If even more data arrives after the trigger has fired we can setup another trigger to reprocess the entire window to update the result

## 4. Fusion [Important]
- Sometimes Data Fusion might try to combine several steps into 1 single step
	- Ex. If there are the following steps : Filter, Modify and Summarize the data, Dataflow might try to do all of this together for effeciency
- It can lead to **Parallelization Issues**
	- Ex. If we have a small dataset and we expand it into much larger one, dataflow might think, "there is small input and there is next step, so ill combine this into one step", this causes dataflow to use less number of workers than required

Indicator:
Pipeline is using lower number of workers than allowed, and it is not going as fast as it could.
Therefore stages are not parlellizing effeciently.

Prevention:
1. Use GroupByKey and then ungroup
	1. Forces dataflow to think data is more bigger 
2. Side Input
	1. Take expanded data and use it as a side input to another step. Makes Dataflow handle the data separately instead of combining steps
3. Reshuffle
	1. Reshuffles the data and acts as a break
