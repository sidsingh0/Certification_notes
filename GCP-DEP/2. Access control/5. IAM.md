IAM allows us to manage who the user is and what permissions he has towards resources on GCP
Principal is an entity which can access GCP resources
Therefore the IAM Policies are applied to the principals.
1. User Accounts
	1. For humans
	2. Username Password
	3. Used to access the Cloud resources
2. Service Accounts
	1. Used by cloud resources and VMs
	2. Key/Tokens
	3. Used for automation/scheduled tasks
	4. This account ensures secure communication between 2 resources, ex. If cloud function has to access pub/sub, it needs a service account that allows access to that specific pub/sub. Only granting that account the `Pub/Sub Publisher` role for a _specific_ topic, you enforce the **principle of least privilege**.
#### Types of service accounts
1. Google managed 
	1. Created by google when the resource is created.
	2. It comes with some permissions already, which we can further customize.
	3. Name is predetermined
	4. Used by GCP services
2. User managed
	1. Created by the user
	2. We provide permissions from the start, therefore there is a management overhead
	3. Name can be chosen by the user
	4. Generally used for a very specific task. 
		-  **The Scenario:** You have a Python script running on a server that needs to read daily CSV files from Cloud Storage, process them, and write the results to a BigQuery database.
		    - **Specific task:** This account exists _only_ for this data pipeline.
		    - **Permissions:** It starts with zero access. You have to manually assign it two specific roles: `Storage Object Viewer` (to read the CSVs) and `BigQuery Data Editor` (to write the results).
		    - **Management overhead:** If the pipeline later needs to publish an alert to Pub/Sub, you have to manually go in and add the `Pub/Sub Publisher` role.

#### Service Account Admin
In order to create, assign permissions, delete/disable these user-managed service accounts, we need to have this permission.

# Permissions and roles
Permissions are granular actions that we can authorize a principal (User/Service account) to take.
Roles are just a collections of permissions.

### Types of roles
1. Basic roles
	- IAM Basic roles (**Owner**, **Editor**, **Viewer**) can be assigned at every level of the Google Cloud resource hierarchy, as well as on individual resources that support resource-level IAM policies. 
	1. Owner role
		- Full access to all the resources
		- Can manage roles and permissions
		- Ex. Project Admins, team leads
	2. Editor role
		- Read/Write access to most resources
		- CANNOT manage roles and permissions
		- Ex. Developers
	3. Viewer
		- Read-only view
		- Cannot modify anything
		- Ex. Client, Auditor
2. Predefined roles
	- These roles define common use cases
	- They reduce managerial overhead
	- Specific to a GCP Service/API
3. Custom roles
	- Defined and managed by the user, not google
