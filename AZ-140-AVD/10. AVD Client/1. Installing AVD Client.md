AVD client is installed on the blade machines of the users, who are going to use the Session hosts.
Ways to install:

1. Manually
	- We can download the software manually based on our computer
	- Supported Platforms
		- Windows (x64)
		- Windows (x86)
		- Windows (ARM)

2. Deploying using GPO
	1. Download the client
	2. Put the installer in a folder and share that folder on network
	3. Server manager > group policy manager > create a new gpo
	4. Computer Configuration
		 └ Policies
		    └ Software Settings
		       └ Software Installation
	5. New -> Package -> Installer path
	6. Choose deployment method:
		- Assigned: Automatic download
		- Publish: Users download from Control Panel
	7. Choose configuration:
		- Computer configuration: Installed for all users on the computer
			- If asked which is best for organization-wide deployment:
				✅ Computer Configuration
				Reason: Any user logging into the machine can use AVD.
		- User configuration: Only installed for the users linked to GPO
	8. Link the GPO to Domain, OU, Computer Groups
	9. Note that **GPUpdate** wont install the software by itself, a computer reboot is required to make it work

3. Intune
	- It works without Domains, AD etc.
	- MDM: Mobile Device Management
	- Used for:
		- Device Management
		- Application Deployment
		- Policy Deployment etc.
	- Intune requires EMS License to work
	- Good for:
		- Remote users
		- Hybrid environments
		- Cloud-managed devices

4. Microsoft Endpoint Configuration Manager (SCCM)
	- On premise
	- Used for:
		- Software deployment
		- Patch management
		- OS deployment
		- Inventory management

5. Deploying Through Images: Install the AVD client into a reference image.

### User Assignment to Application Groups
If users can install the client but **cannot see desktops/apps or cannot connect**, check:
```
Application Group -> Assignments -> User or Group Assigned?
```
A user launches the Remote Desktop client successfully but does not see any published desktops or RemoteApps.
Most likely cause:
✅ User is not assigned to the Application Group.

## Device Redirection
Allows local device resources to be used inside an AVD session.
Examples:
- Clipboard redirection (copy/paste between local PC and AVD)
- Printer redirection (print to local printer from AVD)
- Microphone redirection
- Drive redirection
They are configured inside Azure AVD -> RDP properties
##### Can also be applied via GPO
Priority Rule (Important)
- If there is a conflict: Domain GPO > Local Group Policy > Host Pool RDP Properties
