- User Data is stored in FSLogix
- FSLogix provides a profile container, so that, no matter what system user connects to, their user data is linked to that system.
- Uses VHD (Virtual Hard Disk) or VHDX (Hyper-V Virtual Hard Disk)
- The user profile appears immediately like a native user profile.

#### User Profiles
- User state when a user logs on to the machine
- Contains images, videos, emails etc.
- Remote User Profile is a partition(a VHD) allows the OS to change too without affecting user data.

#### Features:
1. OneDrive is supported only with FSLogix User Profiles
2. High performance (solves block cached exchange mode)
3. Apart from the standard user profile folders, additional folders can also roam with the user

#### Storing .vhdx user profiles
- The files are stored on Azure Files (Managed FS) instead of on-premise
- How do we stop bob from accessing alice's vhdx files? We use authentication
	- We use Azure AD DS (Basically a managed AD, microsoft runs the DC for us)
	- When Bob logs in:
		1. Azure AD DS authenticates Bob.
		2. Azure Files checks permissions.
		3. Bob gets access to Bob.vhdx.
		4. FSLogix mounts the profile.

# Best Practices
- Storage account and session VM should be in the same region
- Permissions need to match the requirements for profile containers
- Each host pool VM must be of same size and type made with one master image
- Each host pool VM should be in the same resource group
- For best performance, FSLogix profile container and Azure Files should be in the same data center. (Zones)
- Storage Account containing the Master Image must be in the same region where the VMS are being provisioned.
 
___

#### Storage account creation
- Globally unique name
- Stick to 15 character rule
- FSLogix recommends premium storage
- Storage type: File shares
- then create file share from inside of storage account creation (SMB Protocol)
- Setup Active directory

# NETAPP
- We can store FSXLogix Profile Container in 2 ways:-
	- Azure Files: Cheaper and Common
	- Azure NetApp Files: Expensive but Faster

Netapp has high throughput.
Low latency
Supported protocols is SMB, NFS and BOTH together.
Scalable
We can upgrade performance tier as storage grows

Optimized for
- HPC
- Database
- FSLogix

Snapshots
- Netapp has support for snapshots.
- Snapshots are incremental and they only store changes over time on the base snapshot
- Point in time recovery

Backups
- Automatic backups if something goes wrong
- Data replication (Cross region) for disaster recovery

Security
- RBAC (Admin, user, viewer)
- AD DS (traditional)
- Azure AD DS (Managed Azure AD)
- Azure Policy (for encryption policies)
