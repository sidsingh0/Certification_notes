# Storing Image
- Image can be a full copy of the VM or just the OS disk
- If we create a lot of images we should have a Azure Compute Gallery

| Microsoft Marketplace    | Azure Compute Gallery |
| ------------------------ | --------------------- |
| Microsoft manages images | You manage images     |
| Public Images            | Our custom Images     |
| MS controls updates      | We control updates    |
- Generalized Images
	- Created after running "sysprep"
	- Removes computer name, ID, SID
	- Used to create many identical VMs
	- Ex: Windows + Office
- Specialized Images
	- Computer Name
	- User-specific settings
	- Unique Identifiers
	- Specific to one VM
	- Ex: Developer VM
	- Its for a specific use case

- Image Definitions
	- Information about the image
	- Things like
		- Publisher
		- Offer (i.e. Windows 10)
		- SKU (i.e. Enterprise 22H2)
		- Release Notes
		- Memory Requirements
	- You CANNOT deploy a VM from an Image Definition. 
	- An Image Definition is only a description.
- Image Version
	- This is the ACTUAL deployable image.
	- You deploy VnMs from Image Versions.
	- Contains:
		- OS disk
		- Applications
		- Configuration
	- We deploy an **Image Version and NOT Image Definitions**
	- The actual software installed belongs to the Image Version.
	- Conventions: Major(Big change).Minor(Feature Addn).Patch(Small fix)

- Azure Compute Gallery Structure
	Azure Compute Gallery
			│
			▼
	Image Definition
			│
			▼
	Image Version
