Office containers and cloud caching
# 1. Office Containers  

## What Problem Does It Solve?  
  
Office applications generate user-specific data such as:  
  
- Outlook OST files  
- Outlook cache  
- Office settings  
- Teams data (older implementations)  
- Office application data  
  
Without Office Containers:  
  
```text  
User logs into Session Host A  
↓  
Office data created locally  
  
User logs into Session Host B  
↓  
Office data must be recreated  
```  
  
This can lead to:  
- Slower application startup  
- Larger profiles  
- More synchronization activity  
  
---  
  
## What Does Office Container Do?  
  
Office Container separates Office-related data from the normal user profile.  
  
```text  
User Profile  
↓  
FSLogix Profile Container  
  
Office Data  
↓  
FSLogix Office Container  
```  
  
Benefits:  
- Faster Office experience  
- Reduced profile growth  
- Better management of Office data  
  
---  
  
## Configuration  
  
The instructor mentions:  
  
- Registry keys are used  
- Group Policy can deploy settings  
- Golden Images can contain settings  
  
### Best Practice  
  
```text  
Golden Image  
OR  
Group Policy  
```  
  
instead of manually editing every session host.  
  
---  
  
## Exam Takeaway  
  
Know:  
  
**Office Container = Stores and redirects Microsoft Office application data separately from the user profile.**

# 2. Cloud Cache  
  
## What Problem Does It Solve?  
  
Users may access profile data across:  
  
- Multiple session hosts  
- Multiple storage locations  
- Distributed environments  
  
Accessing profile data repeatedly can introduce delays.  
  
---  
  
## What Does Cloud Cache Do?  
  
Cloud Cache creates locally cached copies of profile data.  
  
```text  
Profile Storage  
↓  
Cloud Cache  
↓  
Local Cache  
↓  
Faster Data Access  
```  
  
This reduces the need to constantly retrieve data from remote storage.  
  
---  
  
## Benefits  
  
### Faster Access to Data  
  
Users can access profile information more quickly because some data is cached locally.  
  
### Better Resilience  
  
Cloud Cache can support multiple profile storage providers.  
  
If one storage location experiences issues:  
  
```text  
Storage A  
Storage B  
Storage C  
↓  
Cloud Cache  
↓  
User Access  
```  
  
the user may still be able to access profile data.  
  
---  
  
## What Cloud Cache Does NOT Do  
  
The instructor specifically mentions:  
  
Cloud Cache does **not** primarily improve:  
  
- Sign-in speed  
- Logon duration  
  
Its main goal is:  
  
- Faster profile data access  
- Improved profile availability  
  
---  
  
# Office Container vs Cloud Cache  
  
| Feature | Purpose |  
|----------|----------|  
| Office Container | Redirects and manages Microsoft Office data |  
| Cloud Cache | Caches profile data locally for faster access and resiliency |  
  
### Easy Way to Remember  
  
```text  
Office Container  
= Office Data  
  
Cloud Cache  
= Cached Profile Access  
```  
  
---  
  
# Deployment Methods  
  
The lecture repeatedly mentions:  
  
### Option 1: Golden Image  
  
```text  
Configure Once  
↓  
Capture Image  
↓  
Deploy Many Hosts  
```  
  
### Option 2: Group Policy  
  
```text  
Configure GPO  
↓  
Registry Settings Applied  
↓  
All Session Hosts Updated  
```

# Things You Do NOT Need To Memorize  
  
Do not memorize:  
  
- Registry paths  
- Registry value names  
- Configuration tutorials  
- Microsoft documentation steps  
- PowerShell commands  
  
Microsoft is much more likely to ask:  
  
> What does Cloud Cache do?  
  
than:  
  
> Which registry key enables Cloud Cache?
