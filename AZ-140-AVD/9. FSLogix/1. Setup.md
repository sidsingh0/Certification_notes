User can access any session host and we can load their profile to that session host
This happens by keeping a common storage account and with help of FSLogix, the storage is attached to the session host
Storage account type should be **file share**

## 1. FSLogix Profile Containers  
  
### What is FSLogix?  
FSLogix stores a user's profile inside a virtual disk file.  
Supported formats:  
- VHD  
- VHDX  
### Why use FSLogix?  
- Roaming profiles  
- Consistent user experience  
- Faster logon performance  
- Supports pooled host pools

FSLogix profiles are commonly stored in:  
- Azure Files  
- Azure NetApp Files
```text  
Storage Account  
└─ Azure File Share  
	└─ Profiles  
		└─ User VHDX files  
```

### 3. Azure Files Domain Integration  
Azure Files must **support user authentication** before users can access their profile containers.  
We cannot access Azure Files without user authentication.
Supported identity options include:  
- Active Directory Domain Services (AD DS)  
- Microsoft Entra Domain Services  
- Microsoft Entra Kerberos

**Question:** Users cannot access FSLogix profiles stored in Azure Files.  
**Possible Cause:** Azure Files has not been properly integrated with Active Directory or Entra identity services.

### 4. Required RBAC Role    
**Storage File Data SMB Share Contributor** 
Purpose:  
- Read files  
- Write files  
- Create files and folders within the file share

### 5. Share Permissions and NTFS Permissions  
1. SMB Share Permissions  
2. NTFS Permissions  
###### Important  
If either permission is missing:  
- User profile creation fails  
- Profile loading fails  
- User cannot access their FSLogix container

## 6. Storage Account Requirements
The instructor creates:
- Storage Account
- File Share called "profiles"
- FSLogix profiles are stored in an SMB file share.

## 7. Security Group Usage
The lecture creates:
```
AVD Profile Group
```
Purpose:
- Assign permissions to a group
- Add AVD users to that group
- This is good practice instead of assigning permssions to each individual user

# Key Exam Concepts

## 1. FSLogix Must Be Installed on Session Hosts

FSLogix must exist on every session host that will load user profiles.

### Important

For:

- Windows 10 Enterprise Multi-Session
- Windows 11 Enterprise Multi-Session

FSLogix is usually already included.

However:

- It may not be the latest version.
- Microsoft recommends updating it.

### Exam Takeaway

If profile containers are not functioning correctly:

Check:
- FSLogix installation
- FSLogix version

---

## 2. Custom Images and FSLogix

A common deployment method is:

```text
Golden Image
    ↓
Install FSLogix
    ↓
Configure Registry
    ↓
Capture Image
    ↓
Deploy Session Hosts
```

### Benefits

- Consistent configuration
- Faster deployment
- Less manual work

### Exam Tip

Microsoft prefers:
- Installing FSLogix in the image
- Deploying multiple hosts from the image

---

## 3. FSLogix Configuration Is Registry-Based

Microsoft recommends:

- Group Policy Preferences
- Custom Images
- Registry Settings

to configure FSLogix.

### Why?

Because multiple session hosts need identical settings.

### Exam Takeaway

Best practice:

```text
Group Policy
    OR
Custom Image
```

instead of manually configuring every VM.

---

## 4. Profile Container Location

The session host needs to know where profiles are stored.

The configuration points FSLogix to:

```text
\\StorageAccount\FileShare
```

Example:

```text
\\LPStorageAVD\profiles
```

When users sign in:

```text
User
 ↓
Session Host
 ↓
FSLogix
 ↓
Azure File Share
 ↓
VHDX Profile Mounted
```

### Exam Takeaway

FSLogix requires a profile container storage path.

Without it:

- Profiles won't load.
- Profiles won't be created.

After:

- Installing FSLogix
- Configuring profile containers

A reboot is recommended.

### Exam Takeaway

If configuration changes do not appear to take effect:

Consider:
- Restarting the session host.

## 7. Validation Process

Microsoft recommends validating the configuration.

### Validation Steps

1. Sign in as a test user.
2. Launch Azure Virtual Desktop.
3. Wait for profile creation.
4. Verify profile container creation.

Expected behavior:

```text
User Sign-In
 ↓
FSLogix Starts
 ↓
Profile Container Created
 ↓
VHDX Mounted
 ↓
Desktop Loads
```

### Exam Takeaway

Always validate using a real user login.

## 8. Multiple Session Hosts

Important for pooled environments.

If you have:

```text
Host1
Host2
Host3
Host4
```

All hosts require:

- FSLogix installed
- Same configuration
- Same profile storage location

### Best Practice

Use:

- Golden Images
- Group Policy

to keep all hosts identical.

## Mapped Drive Appears Disconnected

The lecture shows:

```text
Y: Drive
```

displaying a red X.

- Storage account connectivity
- File share accessibility
- Drive mapping

Low.

## Profile Container Fails

Possible causes:

- FSLogix not installed
- Incorrect profile path
- Missing permissions
- Azure Files access issues
- Session host not properly configured

These are common exam troubleshooting scenarios.
