In case we have bought a domain, we generally get DNS services with it. (e.g. GoDaddy)
We can also use Azure's own DNS to manage DNS records instead.
To make this change, we need to:
1. Create a **DNS Zone** in Azure
2. Add NS record in GoDaddy's DNS to direct to Azure's DNS
3. Now Azure resolves DNS queries instead of GoDaddy

___

Suppose we have a Domain Controller which has:
1. AD
2. DNS

Now, if a AVD VM wants to join the domain, it will ask where is the domain controller. It will query the DNS server which will say it is at x.x.x.x IP.
Without this DNS record, the joining will fail.

Our Active Directory DNS and Internet DNS should be separate. Since Active Directory DNS has to be private.

If you see a question like:
- Azure Virtual Desktop session hosts cannot join Active Directory. What should you check first?
Answer is:
✅ **Verify the virtual network DNS settings point to the Domain Controller's DNS server.**

___

- Active Directory stores, users, computers, groups, passwords, permissions. It helps system know if we can trust a user or not.
- Domain controller is basically a VM with Active Directory
	- DNS is also installed on DC, since ADs sometimes add/remove records.
	- We can separate too, but microsoft recommends together.
- A session host can join a domain. This means now we can log in to the session host using AD credentials and the existing local credentials.
- If domain controller is located at `10.0.0.4`, then vNET configuration for DNS should be pointing to `10.0.0.4`. Since session hosts want to find the AD.
- Session Host -> DNS -> DC (With AD)
