7                  In case of Virtual Networks, in TCP/IP, first address and last address are reserved for Network address and broadcast addresses respectively. 
Therefore if we have, 10.0.0.0/30 -> 4 addresses - 2 = 2

- VM inside a subnet/net has a vNIC card (like ENI in AWS). 
- vNIC automatically gets IP from the DHCP service used by the vNET
- VMs inside the same vNET can automatically talk to each other by default
- To prevent unrelated VMs from talking to each other we can use NSG on the subnet. NSG is not a firewall it is just packet filter.
- For vNETs to connect with each other, their address ranges should not be conflicting.
- The non-conflicting vNETs dont automatically connect to each other. We need to set up *peering* for that.
- After setting up peering, we can have a *hub-spoke* model, where one vNET can act as a hub vNET. We can set up firewall in this HUB vNET to police the traffic between different vNETs
- To connect on-premise to vNET, we need *VPN Concentrator* on-premise and *VPN Gateway* in the vNET.
- Or we can use expressroute for a private connection to azure(10GBPS+ ) (it is like aws direct connect)
- Outbound traffic is allowed by default to vNET
- Generally, we create subnets with /24 (251 available addresses + 5 reserved)
  & vNETs with /16 (64k available addresses)
