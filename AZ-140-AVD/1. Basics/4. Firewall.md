Firewall policy is a way to manage our rules. This firewall policy can then be assigned to different firewall deployments.
![[Pasted image 20260531211241.png]]

1. Rule collection groups
	1. Default groups:
		1. Default DNAT (Priority: 100)
		2. Default Network (Priority: 200)
		3. Default Application (Priority: 300)
	2. We cannot edit these rule groups
2. Rule Collection
	1. Set of rules
	2. We can set action as ALLOW / DENY, this action applies to all the rules in the collection
	3. There are three types of rule collections:
		- DNAT
		- Network
		- Application
	4. The rule types must match their parent rule collection category. For example, a DNAT rule can only be part of a DNAT rule collection.
3. Rules
	1. Inbound/Outbound
	2. There are three types of rules:
		- DNAT: 
			- Used to translate public IP addresses to private
			- Firewall listens to the inbound requests, filter the traffic and translate the traffic to internal resources
		- Network
			- Filter based on IP, Protocol, Port like NSG
		- Application
			- Filter based on HTTP/HTTPS, domain names someone has typed

Parent policies allows different firewalls to have same policies
We can create rule collection groups without rule collections and, rule collections without rules

# Route tables
- After creating firewall, we need to enable it.
- To enable it, we need a route table that makes all the traffic go through the firewall.
- The rule should redirect all the inbound traffic from 10.0.0.0/8, since that covers all of the private ips 10.x.x.x, single route catches everything
- If i only associate the route table with subnet A, only A's traffic will be inspected by route table and hence only A's traffic will be routed through Firewall, therefore we need to associate all the subnets to the route table
- We use internal IP of the firewall, since we are routing internal traffic, therefore all the network will flow through azure's internal networks
