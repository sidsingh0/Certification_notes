Can be done using scaling plans (like ASG in AWS)
We provide:
1. General: Our normal schedules and work days
2. Ramp-up: 
	1. We select load balancing algorithm 
		1. Breadth first: Distribute all the users over hosts
		2. Depth first: Distribute all the users to a VM with highest number of connections but hasn't reached its maximum session limit threshold
	2. Start time
	3. Minimum percentage of hosts: If we have 10 hosts and this value is set to 1, then at the **start time**, azure will make sure that atleast 1 more host is available to take the users
	4. Capacity threshold: When currently running VM reaches this number of concurrent conenctions, start a new vm
3. Peak hours
4. Ramp Down
	1. Start time
	2. Load balancing algorithm
	3. Minimum % of hosts
	4. Capacity threshold: Its the opposite of capacity threshold in ramp-up. This means if the number of users are below capacity threshold, start draining users and shutting down
	5. Force logg off 
	6. Delay time before logging out users
	7. Notification message to users
5. Off hours

We can create a schedule and just add it later to a AVD host pool
