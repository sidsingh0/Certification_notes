# AZ-140 Notes: Multi-Factor Authentication (MFA)

## What is MFA?

**Multi-Factor Authentication (MFA)** = Using **2 or more authentication factors** to verify a user's identity.

Authentication factors:

|Factor Type|Description|Examples|
|---|---|---|
|Something you know|Knowledge|Password, PIN, Security Questions|
|Something you have|Physical possession|Phone, Smart Card, RSA Token, Key Fob|
|Something you are|Biometrics|Fingerprint, Face ID, Iris Scan, Voice Recognition|

---

# Important Exam Concept

## Two-Step Verification vs Single Factor

Good MFA:
```
Password + Phone
```

```
Password + Smart Card
```

```
Password + Fingerprint
```

Bad MFA (NOT true multi-factor):
```
Password + PIN
```
Why?
Both are:
```
Something You Know
```

---

Not MFA:
```
Phone + RSA Token
```

Both are:

```
Something You Have
```

---

Not MFA:

```
Fingerprint + Retina Scan
```

Both are:

```
Something You Are
```

# Microsoft MFA Methods

#### 1. SMS Text Message
Process:
1. User enters username/password
2. Microsoft sends a code via SMS
3. User enters code
4. Access granted
Example:
```
Password
+
123456 SMS Code
```

#### 2. Phone Call Verification
Process:
1. User enters password
2. Microsoft calls registered phone
3. User presses a key (e.g. 1)
4. Sign-in approved
Useful if:
- No smartphone
- No SMS support
- Landline available
#### 3. Microsoft Authenticator App
Most common Microsoft MFA method.
Process:
1. User enters password
2. Authenticator app receives notification
3. User approves sign-in
4. Access granted
Benefits:
- More secure than SMS
- Faster
- Microsoft recommended

# HOTP

**HOTP = HMAC-Based One-Time Password**
Characteristics:
- Temporary code
- Used once
- Commonly delivered via SMS or authenticator apps
- Helps prevent replay attacks
Example:
```
Code: 583721
Valid once
```

---

# Smart Cards
Smart cards contain:
- Embedded chip
- Digital certificates
- Authentication information
Example:
DoD CAC Card
**CAC = Common Access Card**
Authentication:
```
CAC Smart Card
+
PIN
```
Attacker would need:
- Physical card
- Correct PIN
---

# RSA Key Fob
Small token device that:
- Generates a changing code
- Usually changes every 30–60 seconds
- User enters current code during login
Example:
```
Current code:
472819

Changes after 30 sec
```

# Microsoft's Preferred MFA Strategy

Microsoft heavily promotes:
```
Password
+
Mobile Phone
```

Typically through:
- Microsoft Authenticator App
- Push Notifications
- SMS Verification
- Phone Call Verification

# Implementing MFA
- If we `enable` MFA -> MFA Optional
- If we `enforce` -> Mandatory (Only available in Per User Basis)
- Or we can just use Conditional Access Policies
- Old versions of apps dont have MFA, therefore we can enable App Passwords instead of the MFA here
- But if we disable app passwords and then enable MFA, those apps wont be usable at all
- We can skip MFA for trusted IPs(ex. company computers)
