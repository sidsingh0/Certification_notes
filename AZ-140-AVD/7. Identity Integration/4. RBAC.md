- Privileges depend on our role in the organization
- RBAC controls what we can do after login (Authorization)
- **Rule of least privilege is always used**
- We can assign rules at following levels:
	- Management Group
	- Subscription
	- Resource Group
	- Individual Resource
- For AVD
	- Resource Group
	 ├─ Host Pool
	 ├─ Workspace
	 ├─ Application Group
	 └─ Session Hosts (VMs)
- 3 generic roles:
	1. Reader - View settings cant modify
	2. Contributor - View, Modify, Delete resources. Can't assign permission to others.
	3. Owner - View, Modify, Delete resources, Assign roles to others
- AVD Related roles
	1. Desktop Virtualization Reader - View All the settings, cant do anything. (Ex. Monitor, Audit)
	2. Desktop Virtualization Contributor -
		1. Manage all AVD resources
		2. Cant assign RBAC 
		3. **Closes thing to AVD Administrator**
	3. Desktop Virtualization User
		1. Use published desktops and applications.
		2. Can't Manage AVD
- Host Pool roles
	1. Reader - View Hostpool Settings
	2. ## Host Pool Contributor:
		Can:
			✅ Create host pools  
			✅ Modify host pools  
			✅ Manage host pools
		Cannot:
			❌ Create VMs by itself (Virtual Machine Contributor required)
- **Application Group = published apps/desktops**
- Workspace Roles
	Remember: **Workspace = container users see when they log in**
	- Workspace Reader
		Can view workspaces.
	- Workspace Contributor
		- Can create and modify workspaces
- [IMP]Operator Roles
	- User Session Operator
		- Can manage user sessions.
		- Examples:
			- Send message to users
			- Disconnect session
			- Log off user
		- Cannot: Manage host pools, Create VMs
		- Think: "Help Desk Operator"
	- Session Host Operator
		- Can manage session hosts.
		- Examples
			- Remove session host
			- Change drain mode
			- View session hosts
		- Think: Hotel Maintennance Operator
- Power roles
	- Power On Contributor
		- Can: Start session host VMs
		- Cannot: Stop them
	- Power On Off Contributor
		- Can do both
- Virtual Machine Contributor
	- CRUD, start, stop, Update VMs
	- If a question says: "User can manage host pools but cannot create session hosts"
		- The missing permission is often: **Virtual Machine Contributor**

### Roles you should know for AZ-140
##### Global Administrator
Most powerful role.
Can do almost everything.
Microsoft recommends assigning this sparingly.
##### Virtual Machine Contributor
Can manage VMs.
Cannot manage access permissions.
##### Desktop Virtualization Contributor
Very important for AZ-140.
Can manage Azure Virtual Desktop resources.
##### Reader
Can view resources.
Cannot modify.

### PIM (Privileged Identity Management)

Instead of permanent admin rights:
User gets rights only when needed.
Example:
- John normally has no Global Admin rights.
- John requests Global Admin access.
- Approved for 2 hours.
- Rights automatically removed.
This is called **Just-In-Time (JIT) administration**.
