Uses **signals** to check if user can access a resource or not
Example:
- If user is outside Japan → Require MFA.
- If device is non-compliant → Block access.
#### Conditional Access Flow
1. **Signal collection**
2. **Policy evaluation**
3. **Decision**
4. **Enforcement**
### Signals
1. Identity
	1. User account
	2. Group Permissions
	3. Role
	4. Example: Admin always requires MFA
2. Device State
	1. Compliant Device (has the latest security patches etc, device types,..)
	2. Non-compliant Device
	3. Hybrid Joined (Entra ID + on premise AD registered device)
	4. Example: Allow access only from intune compliant devices
3. Location
	1. IP address
	2. Country
	3. Trusted Network
	4. Example: Block high-risk countries from accessing
4. Application
	1. Outlook
	2. Teams
	3. AVD
	4. Sharepoint
	5. Example: Allow outlook usage only from managed devices
5. Risk level
	1. Provided by Azure Entra ID protection
	2. Impossible travel
	3. Unusual work hour
	4. Unusual sign in

### Zero Trust Policy
Never trust user always verify

### Common Decisions
- Deny Access
- Grant Access
	1. Require MFA
	2. Require Compliant devices
	3. Require hybrid joined device
	4. Require Approved client apps
	5. Require password  change
	6. Require terms of use
### USECASE: Azure Virtual Desktop (Very Important for AZ-140)
User launches AVD:
1. User authenticates.
2. Conditional Access checks:
    - MFA?
    - Device compliant?
    - Location?
    - Risk level?
3. If requirements are met:
    - Session starts.
If not:
- Connection blocked.
