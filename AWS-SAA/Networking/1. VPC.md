	- 10.0.0.0 – 10.255.255.255 (10.0.0.0/8)  -> in big networks
- Max. CIDR per VPC is 5, 
- for each CIDR: 
	- Min. size is /28 (16 IP addresses)

- VPCs are regional 

___

#### Public IP
- Assigned by AWS from a global pool
- Used for **internet communication**
- Allows:
    - inbound (SSH, HTTP, etc.)
    - outbound (internet access)
- **Can change** if you stop/start the instance (unless using Elastic IP)
#### Private IP
- Comes from your VPC CIDR (e.g. 10.0.0.0/16)
- Used for **internal communication** (EC2 ↔ EC2, EC2 ↔ RDS, etc.)
- **Not reachable from the internet**
- Stays the same for the lifetime of the instance (unless you stop/delete it)

# Subnets
- AWS reserves 5 IP addresses (first 4 & last 1) in each subnet
- A subnet is private or public only based on: if traffic from 0.0.0.0/0(internet) is allowed
- If we want 8 IPs
	- Generally: 10.0.0.0/29
	- However we need to account for 5 reserved IPs, therefore actual IPs in this CIDR block is 
	  8-5 = 4
	- Therefore we take 10.0.0.0/28 = 16 - 5 = 11 IPs, which is more than we required but thats okay

### Internet Gateway
- Devices that allow us to connect to the internet
- Horizonally scalable, HA
- *Each VPC can have only 1 IGW*
- *Routing tables must be configured along with IGW to allow internet access*
- We tell routing table associated with public subnet with destination 0.0.0.0/0 to be directed to IGW
- Internet gateway is free

___

### Route Tables
- **“If traffic is going here (destination), send it there (target)”**
- Components:
	- **Destination** - The **IP range** where traffic wants to go (Example:    - `10.0.0.0/16` → inside your VPC)
	- Target - Where route table will make the traffic go (Ex. NAT, Local(Inside VPC), VPC Peering, )
- So lets say our VPC CIDR range is 10.0.0.0/16, we will add a entry
	- Route 10.0.0.0/16 to `local`
- This entry tells the traffic meant for IPs inside of VPC to stay inside (local) and not go some place else to be resolved
- Generally we create different Route Tables for private and public subnet.

### Bastion Hosts
- If we have a protected EC2 instance inside of the private subnet
- And we want to perform some tasks (like maintennance, probing) / access the instance, we cannot do it directly, since then we will have to make it public
- So we introduce an intermediate instance, which is public and also connected to our instance in the private subnet
- We SSH Bastion host, Bastion Host SSH private instances
- *Bastion host is always kept in public subnet*
- ![[Pasted image 20260429054615.png]]
- We need to make sure, in Bastion Host's Security Group, to only allow inbound from our company's public CIDR blocks/IPs, so random attacker cannot even access the bastion host.
- And the instances inside the private subnet need to allow access from Bastion's Security Group or Bastion's private IP address
- NOTHING ELSE! Both are in same VPC so no issues!!!
