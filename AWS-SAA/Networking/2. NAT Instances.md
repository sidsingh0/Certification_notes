# NAT Gateway
- It is basically a managed NAT Instance
- Scales automatically, high internet bandwidth
- No need to configure Security Groups
- *NAT Gateway cannot be used by instances in the same subnet*
- *NAT Gateway, cannot function without IGW, the flow is, Private subnet -> NAT Gateway -> IGW*
- It has a elastic ip already assigned and is deployed in one AZ
	- Meaning multiple NAT Gateways are required for multiple AZ
- We cannot use NAT Gateway as a BASTION HOST

Now, you might notice, everytime we create a new private subnet, we have to create a public subnet specifically for NAT Gateway to work.
THis is cumbersome, there should be one centralized solution to this:-


# RNAT (Regional NAT Gateway)
- No need to create public subnets just for nat
- No need to create NAT in every AZ
- ==Directly create one single NAT for the entire VPC!==
- This is groundbreaking
- Now, only one NAT is required, it has its own routing table
	- We add a single entry:
		- If request destination is internet, route it to IGW 
- Now, in the each private subnet's routing table, we add:
	- If request destination is internet, route it to RNAT
- RNAT also automatically detects new resources and expands to that AZ
