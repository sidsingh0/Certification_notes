# VPC Endpoint
- All the AWS services have a public endpoint
	- DynamoDB
	- S3
	- SNS
	- SQS etc..
- Ofcourse we can connect to these services over the internet via nat gateway via IGW
- However for secure and private communication through AWS's backbone network, we can use VPC endpoints
- We can connect our instance in private subnet directly to the services!

#### Types:
1. Interface Endpoint
	- Powered by privatelink
	- We can connect to any AWS service using this
	- This creates an ENI which assigns a private IP to our instance
	- It costs money
	- Security groups are configured between the services
	- IMPORTANT:
		- Always use Interface endpoint when connecting from on-premises (even for s3 and dynamodb)
		- Always use interface endpoint when connecting from another vpc 
2. Gateway endpoint
	- FREE
	- Only for 
		- s3
		- Dynamodb
	- We have to use route tables in this case

# VPC Flow logs

- Can go to S3, Firehose, Cloudwach logs
- For querying/bigger analysis with SQL, we can use s3 with athena 
- For creating custom metrics/notifications we can use cloudwatch logs + insight

# Site to Site VPN
- Used to connect out VPC to the on-premise data center
- It has 2 componetns
	- CGW- Customer gateway on customer side
	- VGW- VPN gateway on VPC side 
- it goes over the public internet
- There are also 2 types of CGW
	- Public - Uses public IP of CGW which is exposed publically
	- Private CGW - It is private, so it does not have public IP address. Therefore we use NAT Gateway's IP here
- Even after all this is setup, we need to enable:
	- Route propagation for VPG in route table for the subnets
- Ping uses ICMP protocol
